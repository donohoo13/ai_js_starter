# Agent Skills Overview

One front door for interview sessions, five lenses behind it, and a task file carrying a unit of work from capture to done.

The keystone is **ceremony scales with size; engineering discipline never does**: a one-line chore still gets grilled, built test-first, and validated, because artifacts collapse on small work and rigor never does.

Every path from a grilling session into code passes three fixed stops.

- **surface gate** — work creating or reshaping a user-facing surface proceeds only with a `grill-design` outcome, or composition comes from the API payload by accident.
- **incumbent gate** — every scoped task states `incumbent:` (`none`, `replace`, `extend`), since a missing verdict is not a quiet extend; `replace` runs the demolition pass before the first slice, because a build session still holding the old code treats a design as a diff request.
- **human QA gate** — finishing any change hands the user instructions to see it in action and waits for their verdict; nothing is marked done and nothing downstream recommended until they have seen it work.

`/diagnose` is the third way into code, carrying the QA gate alone; a fix outgrowing a repair becomes a captured task entering through the same front door.

## The chain

```
/grill-me (router; /grill-me @<artifact file> routes by the file's kind + status to the next step in its flow)
   ├─> grill-initiative ──> initiative doc (docs/initiatives/: verbose Direction + thin Portfolio rows) ─> hard stop
   │        ├─ pickup: /grill-me @<initiative> ─> next queued project, one at a time ─> grill-product (brief flow below)
   │        └─ reorientation close (direction contradicts standing docs): CLAUDE.md interim-marker offer + estate-reconciliation recommendation, both on the user's word
   ├─> grill-design ──> grammar check ─> design artifact (docs/designs/) or governed-verdict ─> hands into grill-engineer
   │      (the mandatory first stop for every settled surface-bearing ask; also compiles external-tool mockup prompts, the returned mockup re-entering as a supplied design)
   ├─> grill-engineer (≈8/10) ──┬─ build now ─> /tdd ─> human QA gate ─> /stage-for-commit (user commits)
   │      (chains back into grill-design when surface work arrives without its outcome; build-now states none/extend in-session and a replace verdict disqualifies it, routing to spec it)
   │                            ├─ spec it ──> docs/tasks file (status: scoped, incumbent: verdict, Demolition section when replace, design: artifact link)
   │                            │                 └─> /implement-task ─> demolition pass when incumbent: replace (planner reads + records, executor deletes; type errors = connection map)
   │                            │                        └─> slice loop (/tdd, first-render check, commit per slice; connection map shrinks to zero)
   │                            │                               └─> task-end render pass ─> human QA gate ─> /review-board offer ─> /ship-pr offer ─> stop
   │                            └─ park it ──> /capture-task
   ├─> grill-product ──> design docs / ADRs / capture / nothing — hands up to grill-initiative when workstreams decompose into project-shaped units
   │        └─ product brief (docs/briefs/, status: draft; initiative: back-link when portfolio-spawned)
   │              ├─ single workstream ─> seeds grill-design (surface-bearing) or grill-engineer (feasibility + spec against the code)
   │              └─ multi-workstream ─> /ground-brief (same session) ─> status: grounded ─> fresh session per workstream, in recommended order
   └─> grill-research ─> summary writeup / capture / nothing

/capture-task — park anything, any time; the captured file seeds a later grill-engineer session
/diagnose — the bug front door: feedback loop → repro+minimize → ranked hypotheses → fix via /tdd + human QA gate; no-seam and prevention findings → /capture-task
/curate-context — the gate on prescriptive context files (every CLAUDE.md and CLAUDE.local.md, README.md, .claude/rules/, design docs): loaded on every edit by the skill description and the CLAUDE.md rule, distillation of a session's lessons is one entry path; vocabulary, shape facts, and ADRs hand off to domain-modeling
/ship-pr — the work chain's one door to the remote: push the branch and open a PR documenting QA and the review-board outcome; offered by implement-task and review-board, run only on the user's word
primitives under the hood: grilling, domain-modeling, tdd, skill-creator
```

## Artifact lifecycle

A task file's frontmatter moves `captured` → `scoped` → `in-progress` → `done`. A `captured` task keeps unknowns explicit as `TBD (needs grilling)`; a `scoped` task adds design decisions, test strategy, and slices, written during grilling. The format is defined once in `capture-task/assets/task-template.md`, referenced by three skills. A surface-bearing task links its design artifact via `design:`.

Tiers run initiative → brief → task, mirroring Linear, chained upward by `initiative:` and `brief:`. Raw source material is stored verbatim under `docs/assets/<slug>/`, classified before storage. Lower tiers exist without upper ones: most work enters as a one-off brief or task. No GitHub issues appear anywhere in the chain — the file is the tracker. Push and PR happen only through `/ship-pr`, only on the user's word. `/template-feedback` is the single carve-out, sitting outside the chain entirely: it files issues against the template repo.

## project-init

`project-init` is a one-shot onboarding auditor, run once right after the template lands and never again, on either landing path: a fresh "Use this template" instance, or the payload copied by hand into an existing repo. Detection covers the git platform, CI, stack, tracker, MCP surface, and secret-candidate files not yet in the paired `Read(...)`/`Edit(...)` deny registry; on the copy path only, git archaeology recovers a clobbered pre-existing suite as interview talking points. The interview runs `grilling` as an onboarding auditor over what a repo cannot answer. A missing whole-program typechecker becomes an agenda item branched on adoption cost, not a recorded fact, because the demolition pass reads the compiler's error set as its connection map. The plan is itemized and individually approved across skills, agents, settings, hooks, scripts, and the whole `CLAUDE.md`.

Template residue is cleared (the template's `docs/` artifacts, its `CONTEXT.md` and `ARCHITECTURE.md`, `.claude/rules/template-dev.md`), but not before the template lineage is stamped into `CLAUDE.md` from the local `CHANGELOG.md`. `README.md` is rewritten into the project's own, carrying the template-updates recipe; `package.json` is renamed; single-app destinations get the monorepo collapse offered. Validation checks the suite's 8-of-10 assumptions against this project and hunts the 2-of-10 misfits. Facts land in `CLAUDE.md`; in-place skill edits are reserved for genuine forks mapped in `fork-points.md`. It is strictly user-invoked, and its final approved plan item deletes the skill and this README section; on that self-deletion, `sync-template` and `template-feedback` explicitly survive as the long-lived channels to the template. Later drift is normal work for `grilling` and `curate-context`, not a re-init.

## brand-init

`brand-init` is the ceremony for filling `BRAND_DESIGN.md` and its sole owner. The session runs `grilling` with `domain-modeling` active, framed as a brand partner, opening with the mood-board gate over image files in `docs/branding/moodboard/`. Each image is distilled through the interview — what draws the user, then the attributes extracted from that — never a layout or palette taken wholesale. Outputs are foundations, identity tokens, anchored steering sections, a four-part voice, and anti-goals harvested from the session's own rejections. A missing or empty board raises one confirm: stop and curate, or continue with anchor interrogation. Brand evidence questions read `references/brand-research.md` rather than re-running the research. Brand derivation inside `grill-design` is refused inline and signposted here. It is user-invoked, never auto-chained, re-runnable as a refresh; a refresh contradicting the filled doc halts for the user's pick, per `curate-context`. The exit writes the filled doc through `/curate-context`.

## sync-template

`sync-template` is the pull-based channel for updating an instance. It starts by reading the `Template lineage:` stamp, then fetching the remote with tags namespaced against collision. Each release newer than the stamp is walked as an itemized adaptation interview, and each item is applied clean, adapted to this project's posture, or rejected. A rejection records its reason in `docs/template-sync-log.md` so no release gets re-litigated. The negotiation is seeded with the release's adaptation notes. Writes are working-tree changes only; the user commits, then the stamp is updated. It is strictly user-invoked and child-side: the template never pushes into instances, and running it in the template repo is refused. A missing stamp on a real instance triggers first-run onboarding rather than a failure. The release diff pathspec-excludes the residue set, with `docs/company/` excluded from that exclusion because it is payload skeleton that stays.

## template-feedback

`template-feedback` turns a template complaint plus the session that produced it into a scrubbed GitHub issue, or declines and says why. Triggering is strictly user-invoked via `disable-model-invocation: true`, because a session appraising its own output never fires or fires as deflection. Validation is lookup-heavy, two questions the ceiling. The lineage check comes first: already fixed in a newer release means no issue and a `/sync-template` run, the most common outcome. The sync-log check follows: an already-recorded rejection makes it a known misfit. The local-fork check discloses or rules out a misfire inside an adapted artifact. After the three checks, the session trace is weighed by what the caller asked it to look into.

The verdict is `defect`, `gap`, `misfit`, `upstream`, or `not-the-template`, and reaching the last two is the actual work. A `misfit` is the highest-value output, growing `fork-points.md` from evidence. The evidence gate does not yield to the caller: no narratable trace, no issue. The verdict itself stays an overridable recommendation. The trace is narrated purely in template vocabulary, both the most actionable form for a context-free receiver and already scrubbed for a public repo; a trace that cannot be told that way is itself the `not-the-template` finding. Filing takes one non-skippable confirm showing the rendered body, after a duplicate search; labels are `from-instance` plus a kind label. Running it in the template repo is refused.

## grill-me

`grill-me` is the user-invoked router and the one front door, never model-triggered. Input is an explicit lens, a bare lens, a freeform ask whose lens it infers, or an artifact file; it then hands off to one of the five lenses, each declaring itself in its opening line, so a wrong inference costs one corrective sentence. `/grill-me @<artifact>` reads the file — taxonomy home for altitude, frontmatter for lifecycle — and infers the next step: active initiative → next queued project, draft multi-workstream brief → `ground-brief`, captured task → scoping, scoped task → an `implement-task` offer. Any inferred route is stated in one line before proceeding.

Direction-scale language routes to `grill-initiative` directly, and a missed initiative route costs nothing, because grill-product's scale detection hands up mid-session. The first routing check is settledness of the _what_: a fuzzy or fanning-out ask leads with `grill-product` even in engineering vocabulary, because mis-routing designs the how of an undecided what. The second check is surface shape: a settled ask reshaping something user-facing routes through `grill-design` first, whose grammar check fast-exits into `grill-engineer` when the docs already govern the surface. `grill-engineer` is the default only among settled, surface-free asks; the router then routes once and gets out of the way.

## grilling

`grilling` is the relentless one-question-at-a-time interview, run until shared understanding is reached. Question order takes the biggest decisions first, with a recommendation and its reasoning attached to every question. Facts are looked up in the codebase; decisions are left with the user. The session opens by naming subject and objective, stops when the objective is met, and leaves nothing behind but the shared understanding. It is model-invocable on 'grill' phrases or whenever a plan needs stress-testing before implementation. An ask fitting a lens loads that lens skill instead of this bare primitive.

## grill-engineer

The engineering lens, roughly 8 of 10 sessions: runs `grilling` with `domain-modeling` active, framed as an implementing-engineer peer, with the codebase as ground truth for what exists and Context7 for how the stack's libraries behave. At objective-met it asks one exit question with a size-based recommendation — build now (`/tdd`, validate, human QA gate, `/stage-for-commit`), spec it (the `docs/tasks` file with design decisions, test strategy, and vertical tracer-bullet slices, flipping `status: scoped`), or park it (`/capture-task`). A pure discussion ends with no forced exit. Spec-it owns the full authoring depth, with `references/example-scoped-task.md` as the worked example. A captured task or a `docs/briefs/` brief can seed the session, a grounded multi-workstream brief one workstream at a time; mid-grill fan-out hands up to `grill-product`, since this lens's exits are all singular. Two gates ride on this exit. Surface work enters only with a `grill-design` outcome, and finding neither artifact nor governed-verdict the session chains into `grill-design` first. And every task gets its `incumbent:` verdict here — the one place on every path where that call is made, including the build-now path, which states it out loud and is disqualified outright by `replace`, routing back to spec-it for the zone, the branch, and somewhere to put the connection map.

## grill-initiative

`grill-initiative` is the direction lens one tier above grill-product, per Linear's hierarchy. The session runs `grilling` with `domain-modeling` active, framed as a product-strategy partner. A multi-project ask is distilled into one `docs/initiatives/YYYY-MM-DD-<slug>.md`, shaped by `references/example-initiative.md`. The `## Direction` section is verbose on purpose: it is the constitution downstream sessions inherit, and at direction scale the residue is the deliverable. Doctrine in Direction covers product constraints only — artifact types, homes, and owning skills stay the skills' own. The `## Portfolio` section holds thin project rows in pickup order with status, outcome, dependencies, and done-when. Row status `done` is judged manually; `dropped` rows are kept with their why. Source material at this scale is stored verbatim under `docs/assets/<slug>/`, classified before storage.

At initiative time there are no eager children: briefs and tasks arrive at pickup, one project at a time. The close is a hard stop, like `ground-brief`. A direction contradicting standing docs also offers the interim marker and recommends the reconciliation sweep, both on the user's word; the sweep classifies every standing ADR, task, brief, and design against the Direction. Entry is an explicit direction-scale ask, or grill-product's scale hand-up. A lone feature never manufactures an initiative — most product work is a one-off brief.

## grill-product

`grill-product` is the product/design lens: `grilling` with `domain-modeling` active, framed as a product-design partner. It is grounded in `UI_UX.md`, `BRAND_DESIGN.md`, the existing UI code, and web research into named patterns and published findings, so recommendations come from real-world evidence rather than invented UI/UX concepts. Altitude is what and why, never how. Web-evidence questions dispatch `research-analyst` in the background so the interview continues. Exits carry only what crystallised: design-doc updates, a brief, an ADR, a capture, or nothing. A brief lands in `docs/briefs/`, shaped by `references/example-product-brief.md`, evidence-grounded, implementation-free, at `status: draft`. A brief replacing something already shipping states that plainly in Position, because a silent brief gets read against existing code downstream.

Fog-plus-fan-out is detected mid-session and confirmed with a one-line naming. After that confirm the feature set is consolidated, splitting workstreams on UI/UX seams with restraint, and a settled workstream entry is captured and linked on the spot. A single-workstream brief seeds the next lens in-session: `grill-design` when surface-bearing, else `grill-engineer`. A multi-workstream brief chains into `ground-brief` in the same session, then stops hard. When workstreams decompose into projects, the session names initiative scale and, on the nod, hands up in-session with residue intact.

## grill-design

The composition lens between product and engineering: runs `grilling` with `domain-modeling` active, framed as a design partner at composition altitude — what a user-facing surface looks like, never how it is built. Every session opens with the grammar check against `UI_UX.md`. A governed surface exits in minutes with a stated verdict straight into `grill-engineer`; an ungoverned or strained one runs the full composition interview and writes a design artifact to `docs/designs/`, shaped by `references/example-design-artifact.md`, which the task file links via `design:` frontmatter and `implement-task` builds to. Every settled surface-bearing ask routes through here, and a skip is a stated, auditable verdict rather than a silent decision, because judgment-gated design passes demonstrably undertrigger. Every artifact carries falsifiable Experience intent assertions the build's render checks judge feel against. A supplied design — mock, wireframe, or a mockup this skill compiled a prompt for and the user validated — additionally runs the fidelity contract: classify, store under `docs/assets/`, transcribe its working qualities into a Source fidelity inventory before any doc validation, then weigh every doc-conflict cut against that inventory out loud. Both hand-off exits state whether the composition replaces the incumbent surface or extends it, while `grill-engineer` stays the single writer of `incumbent:`. An unsettled what hands up to `grill-product`; skeletal design docs stop the session with a signpost to `brand-init`; a genuinely new grammar earns a one-time `/curate-context` offer into `UI_UX.md`.

## ground-brief

`ground-brief` is the engineering reconciliation pass between a product-pure brief and the workstream grillings it seeds. It reads the brief and the code each workstream would touch, at orientation depth. Outputs are per-workstream feasibility with the risky bit named, cross-workstream contracts, and a recommended order. Code contradicting the split surfaces a re-split proposal with its costs; product lines are never redrawn silently. The write is gated by one HITL approval, and on approval the pass appends `## Engineering grounding`, applies accepted re-splits, and flips `status: draft → grounded` — the one brief fact not derivable from child task files. It is chained from grill-product's brief exit, or run standalone on a draft, because judging re-splits needs the interview residue. A single-workstream brief is declined; it seeds through the router instead. The close is a hard stop with pickup instructions, one workstream per fresh session.

## grill-research

`grill-research` is the research lens: `grilling` framed as a research analyst, with no build pressure by construction. Sourcing runs Context7 → web search → primary docs. Anything past a quick pull dispatches `research-analyst` in the background, announced in one line. Exits are a summary writeup (`docs/notes/` suggested as its home), a capture, or nothing — the normal case, and it counts as success.

## implement-task

The fresh-session resume door: reads a `scoped` task file from `docs/tasks/` and refuses to build on main, on an under-specified file, on a surface-bearing task carrying neither a `design:` artifact nor a governed-verdict, or on a missing or malformed `incumbent:` verdict — presence checks only, never a judgment of the reasoning, and the build session writes none of those keys itself, since a verdict it supplies is no gate and a zone it draws means reading the incumbent. A doc pre-flight offers once to stage lingering context-file work before the tree splits, so the new branch inherits it; then the session moves into a dedicated worktree, one confirm, declining to a plain feature branch. An `incumbent: replace` task runs the demolition pass first, so neither the build session nor the run doing the deleting ever reads the code that dies, and its compiler error set becomes the build's connection map. Then slice by slice: deep plan, `/tdd`, validate, commit, the task file's checkboxes riding along and status flipping `scoped → in-progress → done`. DONE and DONE_WITH_CONCERNS continue automatically; only BLOCKED stops. Land runs the full suite, a task-end render pass over every touched surface, and the human QA gate — nothing is marked `done` until the user has seen it work — then offers `/review-board` and stops before any push or PR.

## tdd

`tdd` is red before green, one seam at a time, tests only at pre-agreed public seams. Each cycle covers a dependency-bounded neighborhood (the seam's tests plus direct consumers, lint on touched files), with the full suite once at the end. Anti-patterns — implementation-coupled, tautological, horizontal slicing — are cataloged in sibling references. UI seams are the exception: layout, appearance, and composition are never test targets, because jsdom computes no layout, so such tests are design-blind. View logic and behavioral contracts get the full discipline; appearance belongs to the design artifact and the render checks, and appearance-shaped tests in touched files are cleaned up in the same change, re-expressed at a behavior seam where they smuggle a real guarantee. It runs under the hood from build-now and the slice loop, and directly whenever a test can lock something down.

## skill-creator

`skill-creator` is the mandated path for any change under `.claude/skills/`. The `guard-skill-edit` hook denies `Edit` and `Write` on those paths until it loads; the matcher reaches those two tool names only, so a Bash write lands ungated. Authoring discipline is trigger-accurate third-person descriptions, progressive disclosure one hop deep, why-over-MUSTs, and rewriting accreted prose. Limits, frontmatter keys, and sources live in `references/skill-quality.md`. Every substantive change closes with a gut-check handoff of test prompts for a fresh session, because the authoring session is too warm to prove cold-start triggering. Every skill change lands with its checklist: README blurb and fork-points coupling checks. It never runs tests itself — evaluation is the user's fresh session.

## review-board

Multi-agent review over the branch diff against the detected default branch plus uncommitted changes; args scope it to a PR number, commit range, or paths. Seats are registered agents in `.claude/agents/review-*.md` with checklists in `review-board/references/`, in two sets chosen by what the change touches: five for code (correctness, security, reliability, maintainability, performance/operations), three for a documented process (flow continuity, coherence, adversarial), and both where a change mixes them. The documentation board never drops below its three and reads full changed files in every mode, because a prose diff loses the section that gives an edit its meaning. An optional leading mode — `quality`, `balanced`, `speed` — shifts each seat's model tier and read depth rather than flattening the board to one model; with no mode given, gate 1 recommends both and gate 2 confirms composition. The session AI chairs on the session model: dedupe, one confirmed/plausible/rejected verdict per finding, then a decision-first report per `review-board/references/output-format.md`. Dispositions follow a finding's provenance rather than its fix size — anything the reviewed work introduced is fixed in session, and `/capture-task` covers only a pre-existing bug needing investigation or a tradeoff deserving its own decision. On a non-default branch it leaves an always-empty `review:` record commit pinning the outcome to the reviewed tree, which `/ship-pr` reads, and closes with a one-line `/ship-pr` offer when a remote exists.

Strictly human-in-the-loop: the report ends with "which findings should I address?" and nothing is fixed until the user picks. Invoke for pre-PR/pre-merge reviews, security passes, or any "review my changes" request.

## capture-task

`capture-task` quick-captures a bug, feature idea, or chore as `docs/tasks/YYYY-MM-DD-<type>-<slug>.md`. Unknowns stay explicit as `TBD (needs grilling)` rather than invented. There is no interviewing: it mines the conversation for error text, paths, and decisions already made, which matters because a fresh session picks the task up cold. Every capture starts at `status: captured`, omitting the scoped sections. An actionable aside or a drifting conversation earns one capture suggestion — fixing it now is `/diagnose` instead. Nothing is ever auto-filed; if the user doesn't bite, drop it.

## diagnose

`diagnose` is the bug front door for anything broken the user wants understood or fixed now. Before any theorizing it builds a red-capable feedback loop — the phase that _is_ the skill. Next it reproduces and minimizes until every element of the repro is load-bearing. Then it tests 3–5 ranked falsifiable hypotheses with one-variable probes. Landing the fix means a regression test via `/tdd` at a correct seam, the QA gate, and a `/review-board` recommendation when the work outgrew quick-fix size, on a deliberately chosen non-main branch where the team flow requires one. Two findings are first-class: "no correct seam exists" is documented and handed to `/capture-task`, and "cannot build a loop" stops to ask for an artifact or environment rather than guessing. Post-fix, prevention gaps go to `/capture-task`, and a durable gotcha earns one `/curate-context` nudge. Phases are skipped only when explicitly justified; a symptom is not a root cause. Invocation is "diagnose", "debug this", or any broken report to investigate now; parking one stays `/capture-task`.

## stage-for-commit

`stage-for-commit` stages exactly this session's changed files by explicit path, never `git add -A`. After staging it hands back a commit message and stops: no commit, no branch, no push, no AI attribution. Before writing the message it proves the staged set with `git diff --cached --stat`. Files another session staged are left in the index and flagged, because a `git commit` takes the whole index. Same-file collisions with unrecognized hunks are surfaced for the user to decide. It is invoked at the end of a quick chore, feature, or bug, and at the build-now landing only after human-QA confirmation, never auto-chained from an implementation.

## ship-pr

`ship-pr` is the PR landing and the chain's only door to the remote. The PR body carries a summary, QA evidence, and a Review board section: findings by verdict, what was addressed with its fix commits, and what was dismissed with the recorded reasons. With no review data, "Not run." is a valid, self-indicting entry. Structure comes from `.github/PULL_REQUEST_TEMPLATE.md`, scaffolded on first use. Review data is read in order from the `review:` record commit, then session context, then "Not run.". Hard stops are mechanical only: default branch, no remote, dirty tree. Process gaps get one nudge and then the truth in the PR body, because a skill that blocks on process gets routed around. The PR carries no AI attribution; the user is author of record. It is strictly user-invoked and conditional by invocation, not configuration: other skills never run it automatically and make a one-line offer at most. Before touching the remote it takes one confirm showing the exact title and body. A `draft` argument opens a draft PR.

## domain-modeling

`domain-modeling` challenges terms against the glossary, sharpens fuzzy language, stress-tests relationships, and cross-references with code. An ask conflicting with a documented boundary is surfaced as a user decision with its cost, never a silent constraint. The moment a term resolves, `CONTEXT.md` is updated inline. It owns all three doc kinds: `CONTEXT.md`, `docs/adr/`, and `ARCHITECTURE.md`. `ARCHITECTURE.md` is a root topology plus per-context docs, created lazily, one true shape-fact at a time, never a stub; a user wanting the whole map at once gets the survey bootstrap. Format and growth rules live in `domain-modeling/ARCHITECTURE-FORMAT.md`.

ADRs are offered sparingly — for decisions hard to reverse, surprising without context, carrying a real trade-off. A new ADR retires what it replaces in the same change. Every ADR declares a `status` from the five tokens. A new decision greps its area and names what it changes via `supersedes` or `amends`; the retired ADR gets the reciprocal field plus a note on which clause died. `amends` is the default reach, since partial retirement is the common case. Linkage and ownership are stated rather than enforced — the description, `ADR-FORMAT.md`, and the `CLAUDE.md` rule — so noticing what to declare is the skill's job, and an ambiguous grep hit goes to the user rather than a guess. It activates inside grill-engineer and grill-product sessions and on "document the architecture"; otherwise shape updates ride with the code that changes the shape, through `implement-task`'s end-of-task check and review-board's correctness seat flagging a contradicting diff.

## curate-context

`curate-context` governs every `CLAUDE.md` and `CLAUDE.local.md`, every `README.md`, `.claude/rules/`, and `BRAND_DESIGN.md`/`UI_UX.md`. Any edit to those loads it first, whatever brought the edit. The design docs also accept a loaded grill lens; `.claude/skills/` stays `skill-creator`'s, and the descriptive docs go to `domain-modeling`, which holds that seam from both sides. No hook enforces this: the skill descriptions and the `CLAUDE.md` rule are the whole mechanism, which is why both name paths explicitly. Every edit scales its ceremony to the edit while the discipline never scales.

A new rule runs the full pipeline: attribution, admission bar, routing, drafting, net-growth judgment. Attribution sorts a candidate into prompt-steering (A), undocumented convention (B), or model error (C) — only the (B)s survive. The bar rejects anything already enforced by config, documented in a skill, subsumed, or generic. Routing picks the narrowest correct file; the test is who executes the rule. Brand and UX foundations go to the design docs; layout is discovered at runtime. The finished edit is judged on net line growth taken whole, zero being the benchmark. Corrections are verified against the code and land lean, deletions surfaced rather than silent. Model-proposed candidates take per-candidate approval, so no model-invented content lands unseen; user-directed edits are applied on the ask, after the bar's pushback.

The apply step appends by default, and is the point-of-use exception to the prose restatement rule. A near-duplicate strengthens the existing bullet, a contradiction halts for the user to pick the survivor, and a decayed target file is flagged as a restatement candidate rather than appended to again. "Nothing worth writing" is a valid and common outcome of any pass. Distillation triggers are one entry path, suggested at most once, never a session-end ritual; the file-triggered path is the common one, firing whether or not anyone said the word.
