# Changelog

Template releases, newest first. Each entry carries three parts: **what** changed, **why**, and **adaptation notes** for instances whose posture diverges from the shipped defaults (compliance regimes, external trackers, collapsed monorepos). A release is a git tag (`vX.Y.Z`) on `main` matching the entry heading; the `sync-template` skill in an instance walks unapplied entries oldest-to-newest (later releases assume earlier ones landed) and negotiates each into the instance's own posture. In an instance this file is template residue: `project-init` stamps the template lineage into `CLAUDE.md` from the top entry here, then deletes this copy.

## v1.0.1 — 2026-07-29

- **What**: Moves the Node runtime pin off `useNodeVersion` in `pnpm-workspace.yaml` and onto `devEngines.runtime` in `package.json` (`onFail: "download"`), rewrites the `check-install.mjs` remediation message, and makes `gwt-add.sh` exit non-zero when its `pnpm install` fails instead of printing a "Worktree ready" banner and exiting 0.
- **Why**: pnpm 11 removed `useNodeVersion` and ignores the leftover key silently — no warning, and `pnpm config get use-node-version` still echoes the value back, so the pin reads as configured while lifecycle scripts run on whatever Node is ambient. Verified both directions on one machine with ambient Node 26.5.0 and the pin set to 24.17.0: under pnpm 10.32.1 the `preinstall` script ran on 24.17.0, under pnpm 11.15.1 it ran on 26.5.0. `devEngines.runtime` supplies the pinned Node correctly on both, so it is the mechanism that survives a pnpm major bump. The old guard message compounded this by telling the reader their pnpm was too old and to upgrade past 10.16 — the exact move that breaks the pin — and it named no way to check whether the required Node was installed at all; the new message leads with verifying that, and names the two traps that make an absent Node look present (Homebrew's versioned aliases can all symlink to one build, so `/opt/homebrew/opt/node@NN` existing proves nothing; nvm can be installed but never sourced, hiding every version it manages). The `gwt-add.sh` change is independent and is what turned a config problem into a debugging goose chase downstream: `if ! (cd "$target" && pnpm install); then` consumes the failure so `set -e` never fires, and `implement-task` branches on that exit code, so a caller proceeded to run tests in a dependency-less worktree and attributed the failures to its own changes.
- **Adaptation notes**: Instances carrying the shipped pin delete `useNodeVersion` from `pnpm-workspace.yaml` and add the `devEngines` block to `package.json` with their own `.nvmrc` version. Retargeting a Node pin now touches three mirror sites that must agree — `.nvmrc` (what the guard reads), `engines.node` (the range it enforces), and `devEngines.runtime.version` (what pnpm downloads) — so an instance that retargeted only some of them has a guard enforcing one version while pnpm supplies another. Keep `engines.node` bounded (`>=X.Y.Z <X+1`) to match the guard's actual major-pinned contract; an open `>=X.Y.Z` lets a machine be simultaneously engine-valid and guard-rejected. An instance that added pnpm's `nodeVersion` key while chasing this removes it: `nodeVersion` sets the version pnpm _pretends_ when checking `engines`, so it makes engines checks pass against a fiction regardless of the Node actually running. Instances that forked `gwt-add.sh` apply the exit-code change by hand; any automation reading its exit code gets stricter, not looser, so no caller needs relaxing.

## v1.0.0 — 2026-07-28

- **What**: Baseline release. The former two-layer meta-repo (`src/` payload + root tooling) is flattened into a single-layer GitHub template repository named `ai_starter`: the whole tracked tree is the payload. Ships the Claude Code process suite (skills, agents, guard hooks, permission registry), the design and domain doc skeletons, the setup scripts (`doctor.sh`, `check-install.mjs`, `gwt-add.sh`/`gwt-remove.sh`), a pnpm + Turborepo monorepo skeleton (`apps/*`, `packages/*`, pnpm-only installs enforced at `preinstall`), and the `sync-template` update channel this changelog feeds.
- **Why**: Dual-layer maintenance taxed every change twice and the layers drifted despite a lockstep mandate; flattening gives template and instances identical file paths, so updates diff and apply 1:1.
- **Adaptation notes**: Pre-baseline instances (created by copying the old `src/` payload) already share these paths. To adopt the update channel: add the template remote (`git remote add template git@github.com:donohoo13/ai_starter.git`), fetch it (`git fetch --no-tags template main`), copy the skill (`git checkout template/main -- .claude/skills/sync-template/`), and stamp `Template lineage: donohoo13/ai_starter, v1.0.0` into `CLAUDE.md`. One real fix to mirror: brace-form secret deny entries (`Read(**/.env.{local,...})`) do not enforce — verified empirically — so any instance carrying that form replaces it with individually enumerated entries as this baseline's `settings.json` does.
